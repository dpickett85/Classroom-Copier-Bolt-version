### F1 — `AuthExpiredError` before any attempt permanently skips the post; `resume()` never retries it
**Criterion 4 (correctness) / 9 (oversights) — significant**
`server/src/services/transfer-engine.ts:996-1015`, `:1176`, `:1069-1073`

`processItem`'s catch calls `recordItemFailure(item, error)` for **every**
error, `AuthExpiredError` included, *before* rethrowing so `execute()` can
pause. `recordItemFailure` finds no `claimedTargetPostId` and no `targetPostId`,
so it writes the item terminal:

```
outcome: 'skipped', skipReason: 'provider_error',
note: 'Could not be copied (AuthExpiredError). Nothing was written to the
       target course for this post.'
```

But `attemptedAt` is written inside `createWithBackoff`
(`:1315-1318`), immediately before `issueCreate` — and
`copyAttachmentToMyDrive` runs at `:1176`, **before** `createWithBackoff` at
`:1207`. So a token that expires during the attachment-copy phase of item N
terminalizes item N with `attemptedAt` still `null` — nothing was attempted, and
the post is nonetheless permanently skipped. The job then pauses; on
`resume()` the item is no longer `pending`, so it is never dispatched again.
The teacher loses that post, the reconciliation sum still balances, and a
partially-completed Drive copy is orphaned. This is the same class of defect as
the two P0s — invisible from inside the app.

It also contradicts §4.3 fix 3's own reasoning, which the code states plainly at
`:721-726`: `attemptedAt IS NOT NULL` is what makes an item evidence-ambiguous.
The corollary — `attemptedAt IS NULL` means nothing was attempted and the item is
safe to retry — is not honoured on the `AuthExpiredError` path.

**Fix.** In `processItem`'s catch, when the error is an `AuthExpiredError` **and**
the item has neither `attemptedAt` nor a claim, skip `recordItemFailure` and
rethrow directly, leaving the item `pending` for the resume. Everything else is
unchanged: `pauseForReauth` already returns before the completion sweep, so
leaving it pending is consistent with D12 (the reconciler's grace ceiling drains
it to `server_interrupted` if the teacher never returns). The MDB's stated
acceptance is preserved — its P0-1 case injects at post-create, where
`attemptedAt` *is* set and `skipped/provider_error` remains correct.

**Add the gate**, in `reauth-resume.budget.test.ts`: a job with a
`copy_to_my_drive` resolution, `rec.failOnMethods.add('copyAttachmentToMyDrive')`,
asserting after pass 1 that the item is still `outcome: 'pending'` with
`attemptedAt` null, and after `resume()` that it appears **exactly once** in
`rec.createdTitles(rec.since('pass2'))`.

### F4 — the client re-implements the skip-reason partition that `shared` exports
**Criterion 6 (seam integrity) — moderate**
`client/src/components/shared/OutcomePill.tsx:21-32`

`outcomeText` classifies skip reasons with a hardcoded if-chain naming
`duplicate_title`, `user_skip_post`, `user_skip_attachment`, `cancelled_by_user`
one at a time. `shared` already exports the closed vocabulary and its predicates
for exactly this purpose — `USER_SKIP_REASONS`, `DUPLICATE_SKIP_REASONS`,
`isUserSkip`, `isDuplicateSkip` (`shared/src/api-types.ts:77-102`) — and
`reconciliation.ts` on the server uses them. The client does not.

This is a second implementation of a partition whose *first* implementation had
to be rebuilt this stage precisely because it drifted (D14 / Decision G). Add a
sixth `SkipReason` in the user family and the client silently renders it as
generic "Skipped" while the server counts it in `skippedByUser` — the summary
tile and the log row disagree, with no test red.

**Fix.** Use `isDuplicateSkip(skipReason)` and `isUserSkip(skipReason)` in
`outcomeText` and in `OutcomePill`'s `duplicate` predicate. Combined with F2's
loop over `SkipReasonSchema.options`, an unclassified new reason then fails
loudly on both sides of the wire.

### F11 — `hasRubric` in the real adapter is a heuristic that over-reports
`server/src/adapters/google/real-classroom-provider.ts:471`

`hasRubric: work.associatedWithDeveloper === true || work.maxPoints != null`.
`associatedWithDeveloper` means "this coursework was created by the calling
developer project", which has nothing to do with rubrics; so in practice
`hasRubric` reduces to `maxPoints != null` and is true for every graded
assignment. `copyRubricIfAny` (`transfer-engine.ts:1426-1428`) then issues one
`getRubric` per graded post at transfer time and returns `false` when it comes
back null — correct, but it is the per-post round trip the port's own comment
says it was shaped to avoid. Landed in module 4 (`a2440e5`, prior session), so
out of this stage's diff; worth pricing before the first real-Classroom run.

### F12 — duplicate matching is many-to-one, so a repeated source title loses a post
`server/src/services/preflight-engine.ts:134-144`

`destinationByTitle` is a first-writer-wins map from
`sourceType:normalizeTitle(title)` to one destination post, and `duplicateFor` is
a plain lookup. Two source posts sharing a title therefore **both** match the
single destination post and are **both** resolved terminal
`skipped`/`duplicate_title` — the second is never copied, even though the
destination holds only one. Teachers duplicating a post inside a unit is not an
exotic case. PM §6.2's enumerated cases do not cover it and the F15 fixture does
not seed it, so this is a decision to take rather than a bug to patch: either
consume matches one-for-one, or state that N source posts collapse onto one
destination match and say so in the disclosure copy. Needs a fixture case either
way.
